## 三、已确认的结论（带条件）

1. **机制层已稳定**：双缓冲（`videos=2`）、`swap>=1`、`visibleSeek=0`、reset 只发生在 hidden / opacity=0 / 非 active 的旧层、连续第二次播放正常、过渡窗口异常帧绝大多数为 0。
2. **旧的 −0.85 ~ −1.0 秒"不同步"是测量假阳性**：旧口径只看元素自身 `opacity/visibility`；使者元素基础 CSS 就是 `opacity:1`，入场阶段其实被祖先瓶体的透明度/缩放与 crop 裁切遮住。
3. **改用"有效可见"口径后**（祖先链 opacity 累乘 × visibility/display × transform 后真实矩形 × crop 交集面积 > 50%），桌面 Chrome 四位使者 **Δ1 = Δ2 = 0 ms**（风信兔/光尾狐/暖山熊/云栖考拉，各多次）。
4. **但人工真机观察仍有异常**：有时"使者挡在瓶前"、有时"空瓶"、有时"晚 1–2 秒进入瓶内"，且**无固定规律**。
5. 因此：**问题尚未关闭**。桌面环境无法复现真机的抖动，判定为"异步时序竞争 / 多事件源未统一收口"（媒体就绪时间随设备与网络剧烈波动）。

**iPhone Safari 操作**

1. Safari 打开上面的网址（把 `item` 换成要测的角色）；
2. 页面顶部点 **开始记录**（若只看到地球画面，向上滚动到最顶部找深色控制栏）；
3. 等约 4 秒，页面下半部分出现"轻抚一颗心星"提示后，**在画面里点那颗心星**；
4. 走完第一次"出瓶 → 前场 → 回瓶"；
5. 回到顶部点 **导出 timeline.json**（Safari 可能先打开文件预览，用分享/存储到"文件"App 保存即可）；
6. 每位角色重复 3–5 次，**异常样本与正常样本都要留**。

**华为 / Android 浏览器操作**

1. 华为自带浏览器（或 Chrome for Android）打开同一网址；
2. 顶部 **开始记录** → 画面里点 **心星** → 走完第一次流程；
3. 点 **导出 timeline.json**（会落到"下载"里）；
4. 同样每位角色 3–5 次，正常/异常样本都要。

**导出文件命名与回收**：文件名形如 `run-<时间戳>-<随机码>-timeline.json`。采集完把文件发回给 C（或放到共享目录），每个 JSON 内含 `runId / character / browser(UA) / buildHash / network / viewport / events / frames / anomalies`。
